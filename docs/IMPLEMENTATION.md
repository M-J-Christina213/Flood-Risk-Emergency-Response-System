# Implementation and acceptance evidence

This document supersedes the readiness claims in `SUPERVISOR_MEETING_STATUS.md` where authentication, assignment, automatic alerts or model auditing have changed. That status file is retained as the supervisor-demo baseline. Unrelated local changes, original DB records and original model bytes were preserved.

## Data and application trace

`Flood_level/**/*.pdf` → `scripts/batch_extract.py` (`extract_pdf`, guarded main) → `outputs/water_levels_raw.csv` → historical `clean_dataset.py` (zero-filled rainfall, source-year filtering) → historical `feature_engineering.py` → historical `fix_target.py` (second shift after filtering) → `model_evaluation_fixed.py` / `model_evaluation_extended.py` / `hybrid_model.py` → `outputs/ml/models/random_forest_fixed.pkl` → `app/main.py` → web/mobile station views. These historical scripts can overwrite outputs; they were inspected, not rerun as part of setup.

Corrected research path: source/clean CSV provenance join → `app/ml_pipeline.py` → `scripts/train_ml.py` → versioned research bundle. It has not replaced the legacy model. Manual import path: `/imports` → additive observation/provenance records → independent CLI worker → shared features + original active RF → persistent prediction event → validity/freshness gate → persistent prototype alert → targeted subscriber queue → test/web/Expo attempt → personal acknowledgement. The retained legacy station CSV response is explicitly historical; newer manually imported inference events are served on the existing station routes. Replay events remain separate and cannot replace manual data.

## Storage and operational limits

Current verification: 13 Python regression/integration tests, 23 legacy compatibility checks and 12 browser workflow checks. The PDF fallback test imports 12 supported station rows and records 28 rejected/out-of-scope rows from a real digital report; repeat import is suppressed. This verifies that report format, not every historical format. A separate validation-only smoke run confirms that no holdout predictions are exported. See `research/verification/checks.json`, `integration.json`, `browser.json` and `research/runs/validation-smoke/validation_summary.json` for machine-readable evidence.

`users_v2` stores salted PBKDF2 hashes and roles. Opaque 8-hour session tokens are hashed in `workflow_records_v2`; passwords and raw tokens are not returned in staff listings. Versioned JSON entities store sessions, observations, import summaries/errors, inference events, alert metadata, subscriptions, deliveries/attempts, acknowledgements, report details, manual actions and audit records. Unique keys handle retries and repeated rows; conflicting station/time readings preserve the original and log rejection. Imports commit accepted rows with explicit rejected-row reasons, not an all-or-nothing claim.

Run a single local worker/import operator per SQLite DB. Concurrent multi-process import races, durable OS service supervision, database growth limits, pagination and production load handling have not been validated. Failed inference events are retained and not retried automatically; correct rejected data through a reviewed correction workflow before reprocessing, rather than silently overwriting observations. Scheduled delivery retries stop after three attempts. Expo tickets are provider-accepted only; there is no device-delivered state without receipts.

Reports can be submitted without authentication; staff-only listing protects report coordinates/descriptions from public enumeration. Anonymous reports have no owner account or public tracking endpoint. Administrative assignment can name an active coordinator. Assigned work is restricted to that coordinator or an admin. Legacy `new/verified/dispatched/resolved` fields are preserved and map to the v2 lifecycle; legacy calls cannot skip assignment. A legacy dispatched record appears as in-progress with assignment metadata absent until reviewed; no old audit history is fabricated.

Default freshness is six hours, cooldown one hour and history gap ceiling 72 hours. These are configurable engineering policies, not certified hydrological horizons. Replay alert generation is opt-in in the CLI, tagged simulation and excluded from operational predictions; use a separate replay DB. Test provider delivery never contacts a real recipient. Web inbox availability is not proof a person viewed an alert; acknowledgement is separately stored.
